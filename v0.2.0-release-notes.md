# v0.2.0

Refactor de compatibilidad para **PHP 8.1–8.4** y **Symfony 6.4 / 7.x / 8.x**. Se
conserva la API que realmente se podía usar en `0.1.x` (las clases como librería).

> **Contexto importante**: en `0.1.x` el bundle **no se podía registrar en Symfony**.
> `SieBanxico::__construct(string $token)` exigía el token, pero el kernel instancia
> los bundles sin argumentos (`ArgumentCountError`); `SieBanxicoExtension::load()`
> estaba vacío; `getConfigTreeBuilder()` usaba `new TreeBuilder()` sin argumentos,
> eliminado del constructor en Symfony 5.3 y que lanza `ArgumentCountError` en 7.x; y
> el alias derivado de la clase (`sie_banxico`) nunca coincidió con el nodo raíz del
> andamiaje (`Estratos_how_to`), lo que habría lanzado `LogicException`. Todo eso
> queda arreglado aquí.

## Requisitos

| Componente | Versiones |
| --- | --- |
| PHP | `8.1`, `8.2`, `8.3`, `8.4` |
| Symfony (`config`, `dependency-injection`, `http-kernel`) | `^6.4 \|\| ^7.0 \|\| ^8.0` |
| Cliente HTTP | Cualquiera conforme a [PSR-18] (y una fábrica [PSR-17]) |

Symfony `7.4` exige PHP `>= 8.2` y Symfony `8.x` exige PHP `>= 8.4`; el paquete
declara `php: >=8.1` y deja que Composer elija la combinación válida.

## Instalación

```bash
composer require estratos/sie-banxico
```

El paquete **ya no impone un cliente HTTP**: `php-http/guzzle7-adapter` pasa de
`require` a `require-dev` + `suggest`. Si tu proyecto no tiene un cliente [PSR-18]:

```bash
composer require php-http/guzzle7-adapter
```

## Novedades

### Registro del bundle y configuración por YAML

El registro del bundle y la configuración son **nuevos** en esta versión: en `0.1.x`
la extensión no leía configuración alguna.

```php
// config/bundles.php
Estratos\SieBanxico\SieBanxico::class => ['all' => true],
```

```yaml
# config/packages/estratos_sie_banxico.yaml
estratos_sie_banxico:
    token: '%env(BANXICO_SIE_TOKEN)%'
    # opcional, si tienes más de un cliente PSR-18:
    http_client: 'app.http_client'
```

Obtén el token en la [página de la API REST] del SIE de Banxico.

Con el token configurado se registran dos servicios:

| Servicio | Descripción |
| --- | --- |
| `sie_banxico.client` | `Estratos\SieBanxico\SieBanxicoClient` con el token inyectado |
| `Estratos\SieBanxico\SieBanxicoClient` | Alias del anterior, para inyección por tipo |

### Inyección por tipo

```php
use Estratos\SieBanxico\SieBanxicoClient;

public function __construct(private readonly SieBanxicoClient $sie)
{
}

$this->sie->exchangeRateUsdLiquidation();     // SF60653
$this->sie->exchangeRateUsdDetermination();   // SF43718
$this->sie->exchangeRateEuroDetermination();  // SF46410
```

### Métodos y firmas nuevas

- `SieBanxico::setToken()`, `SieBanxico::getToken()` y `SieBanxico::client()` (crea el cliente de forma diferida).
- `SieBanxico::getFixExchangeRate()`, alias con la errata corregida de `getFixEchangeRate()`.
- `SieBanxicoClient::__construct()`, con la firma del padre, para inyectar tu propio cliente [PSR-18].
- **`ClientInit()` es idempotente y ya no es obligatorio** antes de consultar un tipo de cambio.

## Compatibilidad hacia atrás

Sin cambios de código para quien usaba el paquete como librería:

```php
use Estratos\SieBanxico\SieBanxico;

$service = new SieBanxico($token);
$service->ClientInit();

$tipoDeCambio = $service->getExchangeRate();
```

Se conservan:

- Las clases `Estratos\SieBanxico\SieBanxico` y `Estratos\SieBanxico\SieBanxicoClient`, con sus nombres y métodos.
- El constructor `new SieBanxico($token)` (el argumento ahora es opcional) y `ClientInit()`.
- Los métodos `getExchangeRate()`, `getFixEchangeRate()` (con la errata original) y `getEuroExchangeRate()`.
- La constante `SieBanxicoClient::SERIES_EURO_EXCHANGE_RATE_DETERMINATION`.

## Cambios que requieren atención

- **`Configuration::ROOT_NAME` pasa de `Estratos_how_to` a `estratos_sie_banxico`**, y se eliminan `Configuration::NODE_TEST` y el nodo `test_node`. Eran restos del andamiaje de la plantilla del bundle: la extensión tenía `load()` vacío, así que **esa configuración nunca se leyó** y ningún usuario pudo haberla usado. Si tenías un bloque `Estratos_how_to:` en tu aplicación, bórralo (nunca tuvo efecto) y usa `estratos_sie_banxico:` si quieres registrar los servicios.
- Los métodos de consulta ahora declaran tipo de retorno `mixed`, y los archivos de `src/` declaran `declare(strict_types=1)`.
- Eliminados `tests/App/AppKernel.php`, `tests/App/config.yml` y `tests/php-cs-fixer.config.php`: el kernel de pruebas apuntaba a una clase inexistente (`Estratos\SieBanxico\EstratosSieBanxico`) y la configuración de php-cs-fixer usaba la API de la versión 2.
- `extra.branch-alias` pasa de `3.0-dev` a `0.2-dev` para reflejar la numeración real del paquete.

## Verificación

- **46 pruebas / 98 aserciones**, incluido un test de integración que registra el bundle y mapea la configuración a través de `MergeExtensionConfigurationPass` (el camino que estaba roto en `0.1.x`).
- Suite ejecutada contra **Symfony 6.4.48, 7.0.10 y 7.4.21**.
- **PHPStan nivel 6** sin errores.
- CI con matriz de PHP × Symfony, incluyendo **Symfony 8.0 sobre PHP 8.4**.
